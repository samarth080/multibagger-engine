# Multibagger Engine — v0.2 Universe + Store + Backtest Design

**Date:** 2026-07-12
**Status:** Approved (autonomous mode)
**Scope:** Sub-project 2: full-universe ingestion, DuckDB run store, point-in-time backtesting harness.

## 1. Goals

1. **Universe ingestion** — replace curated ticker lists with real NSE index
   constituents (NIFTY 500 / Midcap 150 / Smallcap 250 / Microcap 250) plus the
   full NSE equity list, downloaded and cached, exposed as universes.
2. **Run store (DuckDB)** — persist every analysis snapshot so scores become a
   queryable time series (`mbe snapshot`, `mbe history`). This is the data resource
   the future self-calibration loop feeds on.
3. **Backtest harness** — the headline: measure whether our scores actually
   predict forward returns, with honest point-in-time discipline. Output:
   information coefficient (Spearman IC), decile spreads, hit rates per cutoff
   date, written to markdown + DuckDB.

## 2. Point-in-time discipline (the hard part)

- **Fundamentals:** a fiscal year's statements are treated as *available* only
  from FY-end + 90 days (Indian filing lag). `truncate_financials(fin, cutoff)`
  drops any year not yet available at the cutoff.
- **Prices:** `truncate_prices(prices, cutoff)` cuts the frame at the cutoff;
  technicals are computed on the truncated frame only.
- **Market cap as-of:** approximated as current shares_outstanding x price at
  cutoff (split-adjusted). Documented approximation: buybacks/issuances between
  cutoff and today distort it slightly.
- **Non-point-in-time fields** (insider %, institutional %): excluded from
  backtest scoring inputs (set to None) so they cannot leak.
- **Yahoo constraint:** only ~5 annual periods of statements exist, so
  fundamental cutoffs are limited to ~2 usable rebalance dates (e.g. mid-2024,
  mid-2025 with 1-2y forward windows). The harness takes arbitrary cutoff lists
  so a deeper data provider immediately deepens the backtest. This constraint is
  printed in every backtest report.

## 3. Components

```
src/mbe/
├── data/universe_nse.py   # download+cache NSE index constituent CSVs -> tickers
├── storage.py             # DuckDB: runs(run_id, as_of, universe) + results(per ticker)
└── backtest/
    ├── pointintime.py     # truncate_financials, truncate_prices, availability_date
    └── harness.py         # run_backtest(universe, cutoffs, horizon_days) -> BacktestReport
```

- `universe_nse.py`: sources = niftyindices.com CSVs (`ind_nifty500list.csv`,
  `ind_niftymidcap150list.csv`, `ind_niftysmallcap250list.csv`,
  `ind_niftymicrocap250list.csv`) and NSE `EQUITY_L.csv` (full list). Browser UA
  header; DiskCache JSON with 7-day TTL; SYMBOL -> SYMBOL.NS. On download
  failure: clear ProviderError (universes are additive; curated lists remain).
- `storage.py`: DuckDB file `data/mbe.duckdb`. Tables:
  `runs(run_id TEXT, as_of DATE, universe TEXT, created_at TIMESTAMP)`;
  `results(run_id, ticker, investment, multibagger, confidence, risk_score,
  trend_state, price, market_cap, pillars_json, metrics_json)`. API:
  `save_run(screen_result, universe) -> run_id`, `history(ticker) -> DataFrame`,
  `save_backtest(...)`.
- `harness.py`: for each cutoff: analyze each ticker as-of (truncated data, no
  leakage fields), rank by chosen score (multibagger|investment|momentum-pillar),
  compute forward return over horizon from cutoff prices; then Spearman IC,
  decile (or quintile for small N) spread, hit rate (top-quintile beat universe
  median). Skips tickers lacking data at cutoff (recorded). Pure computation
  separated from data fetch for testability.

## 4. CLI additions

- `mbe universes` now lists dynamic NSE universes too.
- `mbe snapshot UNIVERSE` — screen + persist to DuckDB.
- `mbe history TICKER` — score time series from the store.
- `mbe backtest UNIVERSE --cutoffs 2024-07-01,2025-07-01 --horizon 365 --score multibagger [--limit N]`
  — writes `reports/backtest_<universe>_<score>.md` and persists summary.

## 5. Testing

- pointintime: hand-built fixtures — availability lag honored, truncation exact,
  no leakage of insider fields (unit test asserts they are None in as-of info).
- harness scoring math: synthetic universe where high scores were assigned to
  known future winners -> IC == 1.0; shuffled -> IC ~ 0; decile spread sign.
- storage: round-trip run save/load in tmp DuckDB.
- universe_nse: CSV parsing from a fixture string; live download marked network.
- Live verification: real backtest run on an NSE universe subset; snapshot+history.

## 6. Success criteria

1. `mbe backtest` produces an IC/decile report on real NSE data with point-in-time
   discipline and explicit caveats.
2. `mbe snapshot`/`mbe history` persist and retrieve real runs.
3. NIFTY universes download live (or fail loudly, never silently).
4. All offline tests pass; no regression in v0.1 suite.
