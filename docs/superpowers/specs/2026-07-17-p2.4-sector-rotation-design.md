# P2.4 — Sector Rotation & Tailwind Intelligence

**Date:** 2026-07-17 · **Status:** Approved design, amended after code review
**Goal:** Detect which industries are accelerating (price + fundamentals) before
it is obvious in any single company's trailing statements — the "TCS problem"
(great history, cooling industry) and its inverse (ordinary company, heating
industry). Plus a curated, descriptive-only policy/theme tag layer — the seed
of P2.5's causal graph, explicitly not scored.

## Signals (`analysis/sector.py`, pure functions)

Groups = companies in the *current run's universe* bucketed by Yahoo
`industry`, falling back to `sector` when the industry group is too small.
Both signals aggregate per-member values already computed by existing engines
— no new data source.

| Signal | Computation | What it reveals |
|---|---|---|
| Sector relative strength | median member 6m/12m price return minus universe median (leave-one-out for the per-stock pillar) | is money moving into this industry? |
| Sector fundamental momentum | median member latest-YoY revenue growth minus prior-YoY; same for operating margin delta | is the *industry's* demand accelerating, not just one firm's? |

→ `SectorScore` per group (0–100, benchmark-table scored, evidence rows with
member counts) and a per-stock **Sector Momentum pillar** value.

## Wiring — post-pass, not in `build_scorecard`

`build_scorecard` stays a pure per-ticker function. Sector context is computed
as a **post-pass** wherever a universe exists:

- `screen()`: after the per-ticker loop, group bundles, compute `SectorScore`s,
  then `apply_sector_pillar(bundles, context)` augments each card's
  multibagger score (pillar weight 0.12, existing weights scaled ×0.88;
  renormalized away when context is absent, same missing-data semantics as
  every other pillar).
- Harness: per cutoff, collect bundles first, post-pass, then extract scores.
  Bundles are light (no price frames); ≤250 in memory is fine. Both the base
  and augmented multibagger scores are extractable from one pass — the
  ablation compares them on identical inputs by construction.
- `mbe analyze` (single ticker): **no sector pillar** — there is no universe in
  scope and a store lookup would be silently stale. Report shows the curated
  tags (static lookup, always available) and "sector momentum: n/a — computed
  in universe screens." Honest absence over invented context.

Aggregation rules: leave-one-out median for the per-stock pillar (a stock's own
return must not masquerade as its industry's tailwind — it is already paid by
the Momentum pillar); full-group median for the standalone sector ranking.
Industry group needs ≥4 members (≥3 excluding self) else fall back to sector;
if the sector group is also <4, pillar confidence 0. Members missing a
component drop out of that component's median; evidence rows record n.

New fields: `TechnicalState.return_126d` / `return_252d` (computed from
already-truncated prices — point-in-time safe by construction).

## Curated tailwind tags (`scoring/sector_themes.py`) — descriptive only

Data-not-code table: Yahoo sector/industry string → list of
`(theme, direction, one-line reason)`, plus a `curated_as_of` date printed
wherever tags appear (staleness must be visible). Keys are validated against
the known Yahoo vocabulary by test. Shown in reports and `mbe sectors` as
narrative context; **never scored** until a future increment earns it a score
via its own validation.

## New surface

`mbe sectors <universe>` — runs the screen, prints the sector ranking table
(SectorScore, components, member count, top members) and each group's tags.
No new persistence in v1 (derivable from snapshots; schema change deferred
until the pillar is validated). Per-ticker report gains one line under
Sector/Industry: sector-momentum rank when computed, plus tags.

## Validation (pre-registered, same discipline as P2.1/P2.3)

Ablation `scripts/ablation_sector.py` on the cached panels — US smallcap ×2
(disjoint) + India extended cutoffs — 2y horizon, one run scoring both
variants: **the pillar enters MULTIBAGGER_WEIGHTS only if augmented-multibagger
mean IC ≥ base-multibagger mean IC in the majority of samples.** Standalone
sector-momentum IC is also reported for attribution. Weight fixed at 0.12
before looking at results; no weight sweeping (2-cutoff recalibration was
refused in v0.2 for exactly this curve-fitting risk). Fail → pillar demoted to
descriptive; the sector table, report line, and tags stay (they are disclosure,
not ranking). Either way recorded in the findings doc.

## New caveats (added to harness methodology + findings record)

1. **Sector labels are present-day** — `sanitize_info_as_of` keeps
   `info.sector/industry`, so today's classification is applied to historical
   cutoffs. Mild lookahead; not fixable without historical classification
   data; disclosed like the market-cap approximation.
2. **Survivorship bites sector signals harder** — hot sectors are precisely
   where dead names died (dot-com pattern); a sector-momentum backtest over
   today's constituents overstates the signal. Interpreted alongside the
   existing survivorship caveat.
3. **Universe-relative** — the same stock gets different sector scores in
   different universes; the signal is "vs the screened peer set," stated in
   evidence rows.
